## Domaine 3 — Coffre

**Vérifié sans défaut** (lecture de `apps/vault/crypto.py`, `formats.py`,
`services.py`, `keys.py`, `upload_handlers.py`, `validation.py`) :

- **AES-256-GCM**, clé de 32 octets.
  - Le nonce est aléatoire (96 bits, `secrets.token_bytes`) et tiré à chaque appel.
  - Chaque version de document et chaque texte scellé a sa propre DEK neuve : un
    nonce ne sert donc qu'une fois par clé.
  - Le chiffrement des DEK sous une même KEK utilise aussi des nonces aléatoires de
    96 bits : la borne des anniversaires (environ 2³² chiffrements par KEK) est hors
    de portée d'une plateforme de cette taille.
- **Données associées** :
  - **contenu** : format, contexte, thèse, document, version, niveau ;
  - **DEK chiffrée** : la même chose et le `kek_id` ;
  - **texte scellé** : thèse, objet, emplacement (modèle et champ), niveau.
  - Un contexte différent par usage empêche de substituer un chiffré d'un usage à
    un autre. `crypto._check` refuse des données associées vides.
  - Les données associées de `CLAUDE.md` (`document_id || version || level || thesis_id`)
    sont respectées et complétées.
- **HKDF-SHA256** depuis `MASTER_KEY`, avec une étiquette `info` distincte et versionnée
  par usage ; `apps/vault/tests/test_crypto_labels.py` vérifie qu'elles sont
  distinctes et qu'aucune autre n'est utilisée. Les pseudonymes
  sont des HMAC sous une sous-clé dédiée, avec un préfixe d'usage (`ip`, `email`).
- **Changement de niveau** (`change_level`) : chaque version est déchiffrée puis
  rechiffrée sous une **nouvelle** DEK, avec les nouvelles données associées, dans de
  nouveaux blobs. Les anciens blobs deviennent orphelins (illisibles : leur DEK n'est
  plus en base) et les accès explicites sont révoqués en quittant `CONFIDENTIAL`.
- **Aucun clair sur disque** :
  - un seul gestionnaire de téléversement, en mémoire, plafonné à la requête
    (`FILE_UPLOAD_HANDLERS`) : jamais de fichier temporaire ;
  - le déchiffrement d'un téléchargement se fait en mémoire, avec
    `@sensitive_variables` ;
  - réponse `application/octet-stream`, `attachment` avec notre nom de fichier,
    `nosniff`, `no-store`.
- **Seul `vault.crypto` importe la cryptographie** : `tests/test_crypto_imports.py`
  parcourt `apps/` (hors tests et migrations) ; `config/` et `scripts/` ne sont pas
  parcourus pour les imports, mais n'en contiennent aucun aujourd'hui (vérifié par
  `grep`). Les fonctions AEAD privées ne sont utilisées que par `crypto.py` (même
  test, sur `apps/`, `config/` et `tests/`).
- **Textes scellés** :
  - `sealing()` vérifie le droit **et** le niveau avant d'ouvrir la transaction ;
  - pas de `seal` après `audit()` (`LockOrderError`) ;
  - chaque lecture est journalisée (`SEALED_TEXT_READ`) ;
  - les lectures de M12 (flux iCal) n'en font aucune, et un test le vérifie.
- **Téléversements** :
  - extension sur liste blanche, type détecté par le contenu et comparé à
    l'extension, taille plafonnée, fichier vide refusé ;
  - le nom donné au téléversement n'est jamais réutilisé.

**Constats** : SR-10 (secret MFA non lié à l'utilisateur), SR-14 (mémoire).

  - un test fige les empreintes ;
  - `audit()` prend le verrou du journal en dernier (ordre des verrous testé,
    `LockOrderError`).
- **Points de contrôle Ed25519** : clé dérivée de `MASTER_KEY` (étiquette dédiée) ;
  la clé publique s'exporte une fois et s'épingle hors de la plateforme ;
  `audit_verify` vérifie la chaîne et les signatures ; le courriel hebdomadaire ne
  contient que `(seq, hash, signature, horodatage)` (`vault/tasks.py`).
- **Contenu des `details`** :
  - `_check_details` refuse les clés contenant `password`, `token`, `secret`, `otp`,
    `code`, `recovery`, etc. ;
  - les appels relus passent des codes, des identifiants, des dates ISO ou des
    nombres : aucun titre, nom ou adresse (recherche des arguments `title=`,
    `label=`, `name=`, `email=`, `comment=`, `body=`, `purpose=` ; le seul `purpose`
    est un code de `ApprovalPurpose`) ;
  - l'adresse saisie lors d'un échec de connexion n'est gardée que sous forme
    d'`email_hmac`, et l'adresse IP sous forme d'`ip_hash`.

**Constats** : SR-07 (rôle de base non vérifié automatiquement), SR-09 (point de
contrôle global).
